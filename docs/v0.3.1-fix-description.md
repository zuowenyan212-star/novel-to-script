# v0.3.1 修复 PR 描述建议

## PR 标题

修复本地演示模型角色名误识别并优化结构化预览展示

## 功能描述

本 PR 修复 v0.3 本地演示模型在识别角色名时过度匹配的问题，避免将动作、语气或场景描述误合并为人物名称。例如“王林苦笑说道”应识别为“王林”，而不是“王林苦笑”；“台上朗声说道”“一眼沉声说道”等叙述性片段不应被识别为角色。

同时，页面结构化预览区域不再单独展示“章节剧本预览”列表。章节划分仍保留在最终 YAML 的 `chapter_scripts` 字段中，用户可在 YAML 编辑器中查看和编辑，页面预览区域仅保留角色、场景和台词索引，减少重复展示。

## 实现思路

- 在本地规则生成逻辑中新增 `_clean_name`、`_extract_speaker_from_prefix` 等辅助函数；
- 通过动作/语气后缀清洗和黑名单过滤，减少“苦笑、朗声、沉声”等词被拼进角色名；
- 优先从对白上下文中提取可靠说话人，再补充有限的动作上下文角色；
- 前端移除独立的“章节剧本预览”列，但后端 YAML 仍继续输出 `chapter_scripts`；
- 新增回归测试，覆盖“王林苦笑”“台上朗声”“一眼沉声”等误识别场景。

## 测试方式

1. 快速启动项目：`python -m backend.dev_server --host 127.0.0.1 --port 8000`；
2. 打开页面并填入包含“王林苦笑说道”“台上朗声说道”的三章文本；
3. 选择本地演示模型生成剧本；
4. 检查角色表中应包含“王林”，不应包含“王林苦笑”“台上朗声”“一眼沉声”；
5. 检查最终 YAML 中仍包含 `chapter_scripts`；
6. 检查结构化预览区域不再单独展示章节剧本预览列；
7. 执行 `pytest`，确认测试通过。
